IApplicationLogger.cs

IApplicationLogger tells any class that implements it that they must have a method named exactly LogAsync, they must take exactly one parameter of type ApplicationLog, and they must return Task.
It says how the method that handles the log object should look. defines the shape of the action/method, not the data
ApplicationLog.cs says how the log object should look

creating a rule called IApplicationLogger. Any class can choose to follow this rule

Task LogAsync(ApplicationLog log); This is the rule. 
It must have a method named LogAsync, it must accept one ApplicationLog object, and it is a Task (so it can run in the background without blocking the app).

FileLogger and DatabaseLogger follows this rule

Using IApplicationLogger interface we now implement IApplicationLogger logger. now the middleware does not know about the classes, it only knows a logger is present that provides LogAsync fuction.

Now how IApplicationLogger runs the code isnide log writing files.
Think
IApplicationLogger logger = new FileLogger();

logger.LogAsync(log); runs the LogAsync() implementation belonging to the actual FileLogger object.

The middleware calls LogAsync() through the IApplicationLogger interface reference, and that call is recahes to the actual logger implementation(log writing files), such as FileLogger.
