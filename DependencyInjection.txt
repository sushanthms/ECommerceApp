When we have multiple services under one Interface, we register them in program.cs
But the last service overrides all the services above it, so if we want first or second services to use, we cant use them
this problem was there till .NET 8. later it was solved using Keyed Dependency Injection

we have an interface, two services(two files) are there under that interface. we register that two services
in program.cs

builder.Services.AddScoped<IProductService ProductService1>()
builder.Services.AddScoped<IProductService ProductService2>()

the methods in the both services will be same only the code inside the methods will be same
so the http methods is same for both services
we will se only one http methods for the method is in both the ProductService1 and ProductsService2 files
so if we call the http method the services that is registered at last will be called, because it overrides the above service
so this is the problem before .NET 8. it was solved using Keyed Dependency Injection

Using Keyed Dependency Injection

builder.Services.AddKeyedScoped<IProductService, ProductService1>("service1");
builder.Services.AddKeyedScoped<IProductService, ProductService2>("service2");

public ProductController([FromKeyedServices("service1")] IProductService productService)
{
    _productService = productService;
}

for two services the controller is only one
so in controller we have to write the key which service we want
later if we want to change the service we have to change in the controller

If we have two services ad we wnat to use both at the same time. for one feature ProductService1 and for another feature ProductService2

We can keep the controller independent of the key and make the selection somewhere else.

public ProductController(ProductServiceFactory factory)
{
    _productService = factory.GetService();
}

If we have two services and we want to use both at the same time
for one feature ProductService1 and for another feature ProductService2
in this situation we write it like this

public ProductController([FromKeyedServices("normal")] IProductService normalService, [FromKeyedServices("special")] IProductService specialService)
{
    _normalService = normalService;
    _specialService = specialService;
}

based on the feature we can call _normalService.AddProducts or _specialService.AddProducts. we call in the controller.

while registering services, if we use TryAddSingleton instead AddSingleton for two services
now the first registered service will be selected. second registered services cannot override the first registered service

builder.Services.TryAddSingleton<IProductService, ProductService1>();
builder.Services.TryAddSingleton<IProductService, ProductService2>();

builder.Services.TryAddKeyedSingleton<IProductService, ProductService1>("normal");
builder.Services.TryAddKeyedSingleton<IProductService, ProductService2>("special");

When we use same key for both the services during TryAddKeyed it is helpful.
TryAddKeyed is used when we don't want to overwrite someone else's registration.

IEnumerable is used to inject all registered implementations of a service/interface.

IServiceProvider is used when we need to get a service dynamically/manually from DI, rather than having ASP.NET Core inject that service directly.

if we have 3 implementations for one interface, such as sending notification using email, message, and push notification
now if we register the services using IEnumerable, and call them inside a for loop using GetServices we can call all the 3 services

builder.Services.AddScoped<INotificationService, EmailNotificationService>();
builder.Services.AddScoped<INotificationService, MessageNotificationService>();
builder.Services.AddScoped<INotificationService, PushNotificationService>();

public NotificationController(IEnumerable<INotificationService> notificationServices)
{
    _notificationServices = notificationServices;
}

foreach (var service in _notificationServices)
{
    service.Send("Your order has been shipped");
}

We can also use
var services = serviceProvider.GetServices<INotificationService>();

foreach (var service in services)
{
    service.Send("Your order has been shipped");
}
